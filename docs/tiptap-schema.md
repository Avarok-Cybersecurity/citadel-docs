# TipTap schema spec for Citadel Docs

This is the contract between `cdoc-model` (Rust) and the UI's TipTap v2 editor
(`citadel-workspaces/src/components/p2p/CollaborativeEditor.tsx`, `EditorToolbar.tsx`). Every
node, mark and attribute below maps one-to-one onto a model type; the authoritative list is
`schema/prosemirror-schema.json`, generated by `cdoc-pm` and also returned at runtime by
`cdoc-wasm`'s `schema_json()`. This document explains the mapping and names the TipTap
extensions; the JSON is what CI compares against.

## Drift gate (implement first)

Add a vitest that builds the editor's schema and compares it to the generated JSON:

```ts
import { getSchema } from '@tiptap/core';
import spec from 'citadel-docs/schema/prosemirror-schema.json'; // or cdoc-wasm schema_json()
import { extensions, CDOC_DOC_KEYS } from './cdoc-extensions';

test('TipTap schema matches cdoc-model', () => {
  const schema = getSchema(extensions);
  for (const node of spec.nodes) {
    const actual = schema.nodes[node.name];
    expect(actual, node.name).toBeDefined();
    const attrs = node.name === 'doc' ? CDOC_DOC_KEYS : Object.keys(actual.spec.attrs ?? {});
    expect(attrs.sort()).toEqual([...node.attrs].sort());
    expect(actual.spec.content ?? '').toBe(node.content);
  }
  expect(Object.keys(schema.nodes).sort()).toEqual(spec.nodes.map(n => n.name).sort());
  for (const mark of spec.marks) {
    expect(Object.keys(schema.marks[mark.name].spec.attrs ?? {}).sort())
      .toEqual([...mark.attrs].sort());
  }
  expect(Object.keys(schema.marks).sort()).toEqual(spec.marks.map(m => m.name).sort());
});
```

The `doc` node is special: y-prosemirror syncs the fragment, not `doc.attrs`, so the five
document-level values live in `ydoc.getMap('cdoc')` under the same keys
(`meta`, `settings`, `styles`, `numbering`, `comments`); `CDOC_DOC_KEYS` is that list. The
bridge that calls `cdoc-wasm` assembles `{ type: 'doc', attrs: <map>, content: <fragment> }`.

## Conventions

- **Attribute names are the model's serde names** (camelCase). Where the model nests a struct
  (`spacing`, `indent`, `borders`, `page`, `anchor`, `field`), the attribute is a JSON object
  with that struct's fields. TipTap attrs may hold objects; declare them with `default: null`.
- **`null` means inherit.** An unset attribute is `null` in TipTap and absent in the model.
  Never give an attribute a non-null default: the cascade supplies the effective value.
- **Units**: lengths are hundredths of a point (`7200` = 1 inch); font sizes are half-points
  (`24` = 12 pt); border widths are eighths of a point; percentages are fiftieths of a percent;
  line spacing `multiple.lines` is 240ths (`240` single, `276` 1.15, `360` 1.5, `480` double).
  Convert at the edge of the UI control, never in the stored attribute.
- **Boolean formatting marks carry `on`.** `bold {on: true}` sets bold, `bold {on: false}`
  turns off bold inherited from a style (a non-bold word in a bold heading). The toolbar toggle
  adds `{on: true}` or removes the mark; the "explicit off" form is produced when the effective
  value from the cascade is true and the user unsets it.
- **Ids** come from `crypto.randomUUID()` in the UI (the model does not mint ids).
- **Dates** are RFC 3339 strings from `new Date().toISOString()`.

## Nodes

| Node | Content | Attrs | Extension |
|---|---|---|---|
| `doc` | `section+ footnotes?` | (in Y.Map) `meta`, `settings`, `styles`, `numbering`, `comments` | `Document.extend({ content })` |
| `section` | `(header \| footer)* block+` | `start`, `page`, `titlePage` | custom `Section` |
| `header`, `footer` | `block+` | `kind` (`default`/`first`/`even`) | custom `HeaderFooter`; rendered dimmed in the flow, edited via double-click as in Word |
| `paragraph` | `inline*` | `style`, `alignment`, `spacing`, `indent`, `borders`, `shading`, `keepWithNext`, `keepLines`, `pageBreakBefore`, `numbering`, `outlineLevel`, `suppressAutoHyphens` | `Paragraph.extend({ addAttributes })` |
| `table` | `tableRow+` | `style`, `width`, `alignment`, `borders`, `cellPadding`, `columnWidths` | `@tiptap/extension-table` extended |
| `tableRow` | `(tableCell \| tableHeader)+` | `height`, `cantSplit` | `@tiptap/extension-table-row` extended |
| `tableCell`, `tableHeader` | `block+` | `colspan`, `rowspan`, `width`, `borders`, `shading`, `verticalAlign` | `@tiptap/extension-table-cell` / `-header` extended (drop `colwidth`) |
| `text` | — | — | `Text` |
| `image` | atom | `contentId`, `width`, `height`, `alt` | custom `InlineImage` (bytes fetched from the content store by `contentId`) |
| `hardBreak` | atom | — | `HardBreak` |
| `pageBreak`, `columnBreak` | atom | — | custom |
| `tab` | atom | — | custom (`Tab` key handler inserts it) |
| `footnoteRef` | atom | `id` | custom |
| `field` | atom | `field` (`{kind: 'pageNumber' \| 'pageCount' \| 'date', format?}`), `cached` | custom; rendered from `cached`, recomputed by layout |
| `formField` | atom | `id`, `name`, `field` (`{kind: 'text' \| 'checkbox' \| 'dropdown' \| 'date', …}`) | custom |
| `signatureField` | atom | `id`, `signerRole`, `label`, `anchor` | custom; `anchor` is written by layout, read by signing |
| `footnotes` | `footnote+` | — | custom; one per document, last child |
| `footnote` | `block+` | `id` | custom |

Marks allowed on `text`: all. On the other inline atoms: `link`, `comment`, `insertion`,
`deletion` only.

## Marks

| Mark | Attrs | Model field | Extension |
|---|---|---|---|
| `characterStyle` | `styleId` | `RunProperties.style` | custom |
| `textStyle` | `fontFamily`, `fontSize`, `color` | `font`, `size`, `color` | `@tiptap/extension-text-style` + `FontFamily` + `Color`; add `fontSize` (half-points) |
| `bold`, `italic`, `strike`, `smallCaps`, `allCaps` | `on` | the same-named `Option<bool>` | `Bold`/`Italic`/`Strike` extended with `on`; `smallCaps`/`allCaps` custom |
| `underline` | `style`, `color` | `underline` | `@tiptap/extension-underline` extended |
| `verticalAlign` | `value` (`baseline`/`superscript`/`subscript`) | `vertical_align` | custom (replaces `Superscript`/`Subscript`: one mark, explicit baseline) |
| `highlight` | `color` | `highlight` | `@tiptap/extension-highlight` (multicolor) |
| `kern` | `value` (half-points; kerning from that size up, `0` off) | `kern` (`w:kern`) | custom |
| `ligatures` | `value` (`none`, `standard`, `standardContextual`, … `all`: the sixteen `w14:ligatures` values) | `ligatures` | custom |
| `lang` | `value` (BCP 47) | `lang` (`w:lang`) | custom |
| `link` | `href`, `title` | `Marks.link` | `@tiptap/extension-link` (keep `href`, `title` only; `target`/`rel` are presentation) |
| `comment` | `id` | `Marks.comments[]` | custom, `excludes: ''` so several apply |
| `insertion`, `deletion` | `id`, `author`, `date` | `Marks.revision` | custom, mutually exclusive |

Mark order in JSON is the schema's rank order (the table order above); ProseMirror re-sorts
anyway and the Rust decoder reads marks in any order.

## Not used from StarterKit

| StarterKit extension | Replaced by |
|---|---|
| `heading` | `paragraph.style = Heading1…Heading6` (styles gallery) |
| `bulletList`, `orderedList`, `listItem` | `paragraph.numbering = {numId, level}` (flat, multilevel) |
| `blockquote` | `paragraph.style = Quote` |
| `horizontalRule` | `paragraph.borders.bottom` |
| `code`, `codeBlock` | none; no Word equivalent (keep for the `.md` kind only) |
| `history` | y-prosemirror `yUndoPlugin` |
| `dropcursor`, `gapcursor` | kept (editor behaviour, no document content) |

### Home

| Feature | Schema |
|---|---|
| Comments | `comment{id}` marks + thread bodies in Y.Map `comments` (`{id, author, date, text, resolved, parent}`) |

| Feature | Mechanism |
|---|---|

## Migrating a stored document

A document stored as TipTap JSON moves onto collaborative editing once, with
`pm_to_crdt_snapshot(pmJson, clientId)` (`clientId` a `BigInt`). It decodes the JSON with the
same strict decoder as `pm_to_model`, writes the document into a CRDT replica as that client,
reads the snapshot back into a fresh replica and checks that it holds the same document, and
returns a `Migrated`:

- `snapshot()`: the CRDT snapshot (format 2) as a `Uint8Array`, to open with `EditorHandle`.
- `reportJson()`: `{"report": {"losses": [...]}, "problems": [...]}`, the Markdown import's
  shape without `pm` (ProseMirror JSON has no document/template `kind`, unlike a package). The
  ProseMirror mapping is lossless, so `losses` is empty; `problems` lists what the model's
  validation found.

Invalid JSON, an unknown node or mark type, and a snapshot that does not hold the document are
refused with an error naming them; nothing is returned half-migrated.

## Decoding rules the UI must respect

The Rust decoder (`cdoc-wasm` `pm_to_model`) is strict:

- unknown node or mark types are errors (so no stray StarterKit nodes may remain in a `.docx` document);
- `text` nodes must have text; formatting marks on non-text atoms are errors;
- every mark except `comment` appears at most once per node; `insertion` and `deletion` never together;
- missing required attributes (`colspan`, `rowspan`, `columnWidths`, `kind`, `id`, `on`, `value`) are errors; `null` on optional attributes is fine.

Run `check_pm(json)` before `pm_to_model` to get a schema-level diagnostic with a path such as
`doc/section[0]/paragraph[2]/text[1]`.
